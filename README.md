# 🚘 Dynamic Pricing Engine (DPE) — MVP 4.0

Распределенный сервис динамического ценообразования на основе графовых алгоритмов, машинного обучения и адаптивных бизнес-правил, реализующий **аддитивный механизм компенсации (Additive Surge)** с возможностью проведения Switchback A/B-тестирования на дорожном графе Москвы.

---

## 📐 Архитектура Системы

Сервис спроектирован по микросервисной MLOps архитектуре и состоит из следующих ключевых компонентов:
1. **DPE API (FastAPI):** Высокопроизводительный веб-сервис расчета цен (< 30 мс).
2. **Feature Store (Redis & SQLite):** Хранение динамических признаков (спрос/предложение) и истории транзакций.
3. **Traffic Simulator:** Имитатор активности водителей и пассажиров с использованием модели логистической полезности поездок.
4. **CDC (Change Data Capture) / Outbox Worker:** Фоновый воркер для надежной асинхронной передачи событий ценообразования во внешние системы.
5. **Streamlit Dashboard:** Аналитическая панель для визуализации дорожного графа и анализа результатов A/B тестов.

## 🚀 Ключевые фичи MVP 4.0

### 1. Расчет базового тарифа по графу (Dijkstra OD)
Вместо евклидова расстояния расчет времени поездки ($\tau$, сек) и расстояния ($dist$, км) производится на основе дорожного графа по алгоритму Дейкстры:
$$P_{base} = \max(\tau \cdot R_{sec} + dist \cdot R_{km}, P_{min})$$

Где:
- $R_{sec}$ — тариф за секунду поездки (`RATE_PER_SECOND`)
- $R_{km}$ — тариф за километр поездки (`RATE_PER_KILOMETER`)
- $P_{min}$ — минимальная стоимость поездки (`MIN_FARE`)

### 2. Аддитивный Surge (Надбавка)
Для борьбы с умышленным выбором заказов водителями (*cherry-picking*) реализован переход от мультипликативной модели цен ($Price = P_{base} \times Surge$) к аддитивной:
$$Price = P_{base} + \Delta_{surge}$$

Бонус рассчитывается с использованием функции затухания по времени:
$$\Delta_{surge} = \alpha \cdot \tau + \beta \cdot (1 - e^{-\lambda \cdot \tau})$$
Дополнительно применяется **k-Ring сглаживание по графу** для устранения резких ценовых разрывов на границах смежных зон.

### 3. Switchback A/B-тестирование
Для оценки эффективности ценообразования внедрен сплиттер, разделяющий группы по виртуальным часам симуляции:
- **MULTIPLICATIVE** (Контроль): Мультипликативный Surge.
- **ADDITIVE** (Тест): Аддитивный Surge-бонус.

## 🛠️ Запуск проекта

### Вариант 1. С помощью Poetry (Рекомендуемый)
Убедитесь, что у вас установлен Poetry.

1. Установите зависимости:
   ```bash
   poetry install
   ```
2. Запустите тесты:
   ```bash
   make test
   ```
3. Запустите uvicorn-сервер и streamlit-дашборд локально:
   ```bash
   make run-local
   ```

### Вариант 2. С помощью Docker Compose
Запуск всего стека (FastAPI + Streamlit + Redis) в контейнерах одной командой:
```bash
make docker-up
```
- API-сервер будет доступен на `http://localhost:8000`
- Аналитическая панель (Streamlit) будет доступна на `http://localhost:8501`

### Вариант 3. Монолитный деплой на Streamlit Cloud (Zero-Config)
В проекте реализован автоматический фоновый запуск FastAPI API и симулятора трафика внутри процесса дашборда Streamlit.
- Просто привяжите ваш репозиторий к [Streamlit Community Cloud](https://share.streamlit.io/).
- Проект автоматически запустится в полностью бесплатном монолитном live-режиме без необходимости настройки Docker и внешних серверов!
