# Dynamic Pricing Engine

Цена поездки по синтетическому графу Москвы: кратчайший путь и надбавка за спрос. Switchback сравнивает аддитивную надбавку с мультипликативным surge. [Causal Pricing Engine](https://github.com/BigGhut/Causal-pricing-engine) можно подключить сбоку: если он не ответил за 200 мс, цена всё равно считается.

Это симуляция. Граф не OSM, водители не настоящие, городского A/B здесь нет.

## Как считается цена

Запрос снэпится к ближайшему узлу. Dijkstra до назначения даёт секунды и километры с учётом скорости на рёбрах. База поездки:

`max(секунды × 0.15 + километры × 12, 150)`

Спрос к предложению считается по поискам за 5 минут и водителям, которые доезжают до точки за 7 минут. Соседние узлы входят в сглаживание с весом 0.2.

Виртуальный час переключает руку раз в час:

- чётный час — мультипликативная цена, надбавка 0: `база × (1 + 0.5 × max(спрос − 1, 0))`
- нечётный час — аддитивная надбавка сверху базы. В ней ставка за секунду и фиксированная часть, которая насыщается как `1 − exp(−0.0007 × секунды)`

Дальше пол 120 ₽, потолок 1500 ₽ и шаг не больше 15% от предыдущей цены в той же H3-ячейке.

CPE оценивает только аддитивную надбавку против базового тарифа: изменится ли вероятность, что названный водитель возьмёт заказ. DPE спрашивает его в нечётный час и только если в поиске есть `driver_id`. Надбавка снимается (`CAUSAL_NO_SURGE`), только если score ниже −0.05 и CPE вернул `ranking_supports_decision: true` — нижняя граница Qini выше нуля. Пока интервал накрывает ноль, порог цену не меняет. Мультипликативный час CPE не трогает. Ошибка или таймаут цену не роняют. Подробности в [CAUSAL.md](CAUSAL.md).

CatBoost в репозитории учится на синтетической конверсии и в эту формулу не входит.

Граф — 70 узлов: Кремль, бульварное и Садовое кольца, ТТК, радиальные хабы и МКАД. Два радиальных ребра разорваны как река. Скорость берётся из телеметрии, иначе из часового профиля заторов.

## Симуляция switchback

Водитель в симуляторе принимает заказ логистической функцией от руб/час после комиссии 20% и 6 ₽/км. На короткой мультипликативной поездке со surge выше 1.1× к полезности применяется дополнительный штраф: это заложенное в модель cherry-picking, не наблюдение за водителями. Штраф не меняет цену. Обе политики считаются на одних и тех же поездках и на одной равномерной случайной величине.

Формула цены живёт в `src/pricing.py`, сборка котировки — в `src/service/`. Модель водителя, порог 900 ₽/ч и штраф cherry-picking лежат в `src/sim/driver_model.py`: это допущения симулятора, не часть котировки.

`python -m src.eval.switchback` всегда пишет обе колонки в [reports/metrics.json](reports/metrics.json). `python scripts/run_simulation.py --no-cherry-penalty` выключает штраф только в живом цикле: в SQLite попадает принятие без штрафа. Ручки `POST /api/v1/virtual_hour`, `POST /api/v1/inject_fault` и `POST /api/v1/telemetry/edge` отвечают только при `SIM_MODE=true` и не входят в OpenAPI.

Утро: спрос на окраине, назначение в центре. Вечер наоборот. Иначе origin и destination равномерны по графу.

Таблица округлена из `reports/metrics.json`. Прогон seed 42, 80 водителей, 96 тиков по 15 виртуальных минут с 07:40, 1443 поездки. CPE в этом прогоне выключен. Повторный запуск перезаписывает файл. Аддитивные колонки совпадают: штраф их не касается.

| | Mult., со штрафом | Add., со штрафом | Mult., без штрафа | Add., без штрафа |
|---|---:|---:|---:|---:|
| Поездок | 708 | 735 | 708 | 735 |
| Принято | 23.9% | 27.1% | 29.5% | 27.1% |
| Принято, короче 5 км | 33.3% из 99 | 73.9% из 92 | 73.7% из 99 | 73.9% из 92 |
| Принято, 10 км и длиннее | 20.4% из 529 | 16.4% из 538 | 20.4% из 529 | 16.4% из 538 |
| Средняя цена, ₽ | 421.4 | 412.2 | 421.4 | 412.2 |
| Средний доход водителя, ₽ | 582.1 | 652.7 | 708.8 | 652.7 |
| CV дохода водителей | 0.851 | 0.703 | 0.769 | 0.703 |

Разрыв на коротких поездках 33.3% против 73.9% полностью заложен допущением. Без штрафа получается 73.7% против 73.9%. На длинных поездках доля принятия и цена в обеих колонках одни и те же: штраф до них не доходит.

96 тиков — одни виртуальные сутки, по 12 часов на каждую руку. Час 7 собран из тика в начале суток и тика в конце, остальные часы — по четыре тика. Метрики по часам лежат в `policies.*.hours`. Пара — чётный час (мультипликативная рука) и следующий нечётный (аддитивная). Разница — доля принятия в аддитивном часе минус доля в мультипликативном.

Бутстрэп по такому числу пар даёт слишком узкий интервал: при ресемплинге почти не видно хвостов. Здесь точный перестановочный тест. У каждой пары оба знака разницы, и наблюдаемая средняя сравнивается со всеми назначениями. Это не доверительный интервал.

В коротких поездках пары 0–1 и 22–23 не входят: в часах 1 и 23 коротких поездок нет (в чётных часах их 4 и 2). Остаётся 10 пар и 1024 назначения, не 4096. В 6 из этих 10 пар хотя бы в одном часе меньше 5 коротких поездок, и у каждой пары один вес: тест говорит о среднем этих часовых долей, а не о 99 и 92 отдельных поездках. Со штрафом средняя разница +0.505, 10 из 1024 назначений не менее экстремальны, двустороннее p = 0.0098. Без штрафа средняя разница −0.008, 928 из 1024, p = 0.9062.

По всем поездкам пары полные: 12 пар и 4096 назначений. Со штрафом средняя разница доли принятия +0.013, 3228 из 4096, p = 0.7881. Без штрафа −0.049, 1450 из 4096, p = 0.3540. Общий разрыв 23.9% против 27.1% по парам часов не отделяется от шума.

Со штрафом CV аддитивной руки 0.703, мультипликативной 0.851, средний доход аддитивной руки 652.7 ₽, мультипликативной 582.1 ₽. Один прогон, seed 42, второго seed нет. CV делит разброс на среднее, поэтому разница CV может получиться из-за того, что аддитивная рука чаще принимает короткие поездки. Без штрафа аддитивная рука остаётся на CV 0.703 и 652.7 ₽, мультипликативная — 708.8 ₽ и CV 0.769. Короткие поездки при этом принимаются почти одинаково. Пока seed один, из CV и среднего дохода отдельный вывод не следует.

## Запуск

Python 3.10+. Датасет не нужен.

```bash
pip install -r requirements.txt
python -m pytest tests -q
python -m src.eval.switchback
python scripts/run_local.py
```

`python scripts/run_local.py` поднимает API с `SIM_MODE=true`, симулятор и дашборд. Дашборд сам сервер не запускает. Публичные ручки: `GET /health`, `POST /api/v1/search`, `POST /api/v1/ping`, `GET /api/v1/graph/state`. Отдельно API без симулятора: `python -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000`.

Локально feature store живёт в памяти. Redis не обязателен.

```bash
docker compose up --build
```

Compose поднимает Redis, API на `:8000`, симулятор и Streamlit на `:8501`. У API в compose включён `SIM_MODE`, иначе симулятор не запишет виртуальный час и скорости рёбер. У API, симулятора и дашборда один файл SQLite. В контейнере CPE выключен. Чтобы включить его локально: CPE на `:8100` и `CAUSAL_ENABLED=true`.
